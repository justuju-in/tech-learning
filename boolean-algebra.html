Why Shorter Is Better

Every gate you remove from a circuit is a real saving:

  • Fewer gates → cheaper chip
  • Fewer gates → less power and heat
  • Fewer gates → a faster signal path

And it isn't only hardware. Read this condition:

if ((a && b) || (a && c)) { ... }

The same thing, simplified:

if (a && (b || c)) { ... }
Simpler logic = cheaper circuits and code that's easier to read and trust. Boolean Algebra gives us the rules to get there — on purpose, not by luck.

What Boolean Algebra Is

A set of rules for rewriting logic expressions without changing what they mean.

You already know algebra

a + 0 = a

a × 1 = a

a(b + c) = ab + ac

Boolean is the same idea

OR behaves like +

AND behaves like · (and AB means A·B)

NOT is the ' mark: A'

One big difference: in Boolean, every variable is only ever 0 or 1. That makes some new rules possible that ordinary algebra doesn't have.

The Laws

Your toolkit for simplification

Each one can be checked with a truth table — none of them is magic.

Identity & Null

What happens when you combine a variable with a plain 0 or 1?

Identity — the harmless one

A + 0 = A
A · 1 = A

OR-ing with 0, or AND-ing with 1, changes nothing.

Null — the takeover

A + 1 = 1
A · 0 = 0

OR-ing with 1 forces 1. AND-ing with 0 forces 0.

In words: "rain OR (something always true)" is always true. "rain AND (something always false)" is always false.

Idempotent & Complement

What happens when you combine a variable with itself, or with its opposite?

Idempotent — repeating is free

A + A = A
A · A = A

Saying the same thing twice adds nothing. (We'll use this trick later!)

Complement — a thing vs its opposite

A + A' = 1
A · A' = 0

"A or not-A" must be true. "A and not-A" is impossible.

Complement is the engine of simplification: whenever you can make an A + A' appear, a whole chunk collapses to 1.

The "Nothing New" Laws

These three work exactly like ordinary algebra — you already use them without thinking.

Double Negation

(A')' = A

NOT of NOT undoes itself. In code: !!x === x.

Commutative

A + B = B + A
AB = BA

Order doesn't matter.

Associative

(A+B)+C = A+(B+C)
(AB)C = A(BC)

Grouping doesn't matter.

Don't memorise these as something foreign. They're the same moves you make with numbers.

Distributive — the workhorse

This is the rule you'll reach for most. It comes in two forms:

A(B + C) = AB + AC   (just like ordinary algebra)
A + BC = (A + B)(A + C)   (this one is Boolean-only!)
The second form does not work with ordinary numbers — try it with 2, 3, 4 and you'll get nonsense. It works here because variables are only 0 or 1.

Absorption — the great shortcut

This one saves you the most time. Two forms:

A + AB = A
A(A + B) = A

If A already decides the result, the extra B is dead weight.

A + A'B = A + B
A(A' + B) = AB

The "mismatched" version — drop the repeated variable from the second term.

Why A + AB = A? Watch:

factor A: A + AB = A(1 + B)
Null: = A · 1
Identity: = A
You can prove every absorption form from the basic laws — but they're so common that it pays to recognise them on sight.

De Morgan's Theorems

How to push a NOT through a bracket

The single most useful rule for gates, circuits, and code.

Theorem 1: NOT of an OR

(A + B)' = A' · B'

"NOT of an OR = AND of the NOTs"

Open thread 4, closed! In Logic Gates you saw that A NAND B and A' + B' always matched. Now you know why: A NAND B = (AB)', and De Morgan's says that equals A' + B'. Same thing, always.

De Morgan's, the Easy Way to Remember

To take a NOT through a bracket, do three things:

  1. Flip every variable (A becomes A', A' becomes A)
  2. Swap the operator (AND ↔ OR)
  3. Drop the outer NOT

It works for more than two variables too:

(A + B + C)' = A' · B' · C'
(A · B · C)' = A' + B' + C'
Picture it on a gate symbol: a NOT "bubble" pushed back through the gate flips the gate type (AND↔OR) and puts a bubble on each input. That's De Morgan's, drawn.

De Morgan's in Code

This is where you'll use it most often as a programmer:

// These are identical:
!(a || b)   ===   (!a && !b)     // Theorem 1
!(a && b)   ===   (!a || !b)     // Theorem 2
Real example. "Block the page unless the user is logged in and verified": 
if (!(isLoggedIn && isVerified)) blockPage();
// De Morgan's makes the intent clearer:
if (!isLoggedIn || !isVerified) blockPage();
"If they're not logged in, OR not verified — block."
Whenever you see !(... && ...) or !(... || ...), De Morgan's can make it readable.

Simplification

Now we use the tools — one law at a time

Let's close those open threads from Logic Gates.

How to Approach a Simplification

A reliable order of attack:
  1. Spot common factors — pull them out with the distributive law.
  2. Hunt for complement pairs — an A + A' collapses to 1.
  3. Use absorption — A + AB = A and A + A'B = A + B on sight.
  4. Push NOTs in with De Morgan's when you see a bracket with a bar.
  5. Clean up the 0s and 1s with Identity and Null.
Apply one law per step, and write its name. Rushing two laws at once is where mistakes hide.

Example 1 — Open Thread 1

Remember the circuit that gave (A + B) · A'? Let's simplify it.

(A + B) · A'
Distributive: = A·A' + B·A'
Complement (A·A' = 0): = 0 + A'B
Identity (0 + X = X): = A'B
Thread 1, closed! (A + B)·A' = A'B. The circuit needed an OR, a NOT, and an AND — but it's really just "NOT A, AND B." Two gates become one idea.

Example 2 — The Majority Function (Thread 2)

Our four-term monster from Logic Gates:

F = A'BC + AB'C + ABC' + ABC
The trick: Idempotent says ABC + ABC = ABC. So we may quietly make two extra copies of ABC — they cost nothing — and pair one with each other term.
Add copies of ABC: A'BC + ABC  |  AB'C + ABC  |  ABC' + ABC
Factor each pair: BC(A'+A) + AC(B'+B) + AB(C'+C)
Complement (X+X' = 1): BC·1 + AC·1 + AB·1
Answer: F = AB + BC + CA
Thread 2, closed! From about 10 gates down to roughly 5. (This says "output 1 when at least two inputs are 1" — the majority vote.)

Example 3 — The Five-Term Table (Thread 3)

The worst one — five product terms:

F = A'B'C' + A'B'C + AB'C' + AB'C + ABC'
Group by pairs: A'B'(C'+C) + AB'(C'+C) + ABC'
Complement (C'+C = 1): A'B' + AB' + ABC'
Factor B' from first two: B'(A'+A) + ABC'
Complement (A'+A = 1): B' + ABC'
Absorption (B' + B·X = B' + X): B' + AC'
Answer: F = B' + AC'
Thread 3, closed! Five terms became two. Check any row of the original table — it matches.

Back to Code

The same rules clean up your conditions

Code Example — A Tangled Condition

if ((a && b) || (a && c) || (a && !b && c)) {
    processData();
}
As Boolean: AB + AC + AB'C
Factor A: A(B + C + B'C)
Absorption (C + B'C = C): A(B + C)
if (a && (b || c)) {
    processData();
}
Three conditions became one clear line. A flowchart drawn from this is far simpler too.

One Elegant Pattern: Duality

Did you notice the laws come in pairs? There's a reason.

The Duality Principle: take any true Boolean law, swap every AND ↔ OR and every 0 ↔ 1, and you get another true law — for free.

Start with:

A + 0 = A

Swap + ↔ · and 0 ↔ 1:

A · 1 = A

Start with:

A + A' = 1

Swap:

A · A' = 0
That's why the toolkit table had two columns. Learn one side, and duality hands you the other.

Challenge — Product of Sums

Remember Product of Sums from the Logic Gates lesson? A product (AND) of sum (OR) terms, like below. The same laws simplify it — the brackets are just multiplied out.
F = (A + B)(A + B')(A' + B)
Multiply first two — use A + BC = (A+B)(A+C) backwards: (A + B)(A + B') = A + BB'
Complement (BB' = 0) & Identity: = A
Now A(A' + B): = AA' + AB
Complement (AA' = 0) & Identity: = AB
Answer: F = AB
Three brackets and six letters collapse to a single AND gate.

Homework — Answer Key

H1. A + A'B = A + B  [Absorption]

H2. AB + AB'C + AB'C' = AB + AB'(C+C') = AB + AB' = A(B+B') = A

H3. (A+B)(A+C) = A + BC  [Distributive, the Boolean-only form]

H4. A'B + AB + A'B' = (A'+A)B + A'B' = B + A'B' = B + A' = A' + B  [Absorption at the end]

H5. (AB')' + A'B = (A' + B) + A'B = A' + B  [De Morgan's, then Absorption] = A' + B

H6. ABC + ABC' + A'BC + AB'C = AB(C+C') + A'BC + AB'C = AB + A'BC + AB'C = AB + BC + AC (the majority function again — try it!)

H7. F = 1 wherever B = 1, plus the row (1,0,1). SOP simplifies to B + AC.

H8. F = A'B' = (A+B)' → this is a NOR gate.

H9. A'B + AB + A'B' = B + A'B' = A' + B → if (!a || b) run();

What We Learned Today

  • Boolean Algebra rewrites logic without changing its meaning — to use fewer gates and clearer code.
  • The laws: Identity, Null, Idempotent, Complement, Distributive, and the great shortcut, Absorption.
  • De Morgan's: flip the variables, swap AND↔OR, drop the NOT. It explained NAND = A' + B'.
  • We closed every open thread from Logic Gates — the long expressions really were shorter.
  • Duality: every law has a partner, found by swapping AND↔OR and 0↔1.
